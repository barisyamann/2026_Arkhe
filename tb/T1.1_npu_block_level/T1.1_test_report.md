# T1.1: YZ Hızlandırıcı (NPU) Blok Seviyesi Doğrulama Raporu

Bu rapor, Yeniden Yapılandırılmış Yapısal YZ Hızlandırıcı (NPU) donanım modülünün (`npu_compute_engine.sv`) bağımsız testbench ortamında (`tb_npu_compute_engine.sv`) gerçekleştirilen işlevsel doğrulama sonuçlarını belgelendirir.

---

## 1. Testin Amacı ve Kapsamı
Bu testin amacı; NPU donanım motorunun (Reshape, 10x8 DepthwiseConv2D, ReLU, Flatten/streaming, FullyConnected, Softmax ve Argmax) hesaplama mantığının doğruluğunu, yeni **ROM tabanlı bellek ilklendirme yapısını ($readmemh)**, **TCM bellek sınır denetimlerini** ve yenilenen **CSR & Interrupt mantığını** doğrulamaktır.

Bu test kapsamında; NPU bileşenleri doğrudan uyarılarak bağımsız (block-level) olarak simüle edilmiş ve log dosyaları üretilmiştir.

---

## 2. DTR Referans Mimarisine Uyumlu Yenilikler
Ön Tasarım Raporu (ÖTR) sonrasında, donanımın gerçek bir TinyConv/TFLite modeline yakınsaması, donanım/yazılım eş-tasarımının doğruluğu ve DTR'de savunulabilir olması için tasarımda şu güncellemeler yapılmıştır:

1. **Gerçek ROM Yapısı ($readmemh):** Sabit/temsili fonksiyonlar (`get_conv_weight`, `get_fc_weight`, vb.) tamamen kaldırılmış; ağırlık ve bias değerleri harici dosyalardan (`dw_weights.mem`, `dw_bias.mem`, `fc_weights.mem`, `fc_bias.mem`) yüklenerek sentezlenebilir ROM dizileri haline getirilmiştir.
2. **Doğru FC Ağırlık Haritalama (Class-Major Layout):** TFLite model çıkış biçimine (`[4, 4000]` tensor yapısı) uygun olarak tam bağlantılı (Fully Connected) katmanı ağırlık indeksleme mantığı `class * 4000 + flat_idx` olarak güncellenmiş ve mock ağırlık dosyası buna göre yeniden hizalanmıştır.
3. **Modüler AXI Denetleyicisi ve Senkron AXI Read FSM (`npu_axi_controller.sv`):** 
   * TCM SRAM belleğe dışarıdan AXI-Lite veriyolu üzerinden yapılan erişimler bağımsız bir denetleyiciye taşınmıştır.
   * Senkron RAM okuma gecikmesini güvenle yönetmek için `R_IDLE -> R_MEM -> R_CAPTURE -> R_RESP` durum makinesi (FSM) entegre edilmiştir.
   * Yazma kanalındaki `mem_wstrb` byte maskeleme sinyalleri `mem_wstrb_lat` saklayıcısına latch'lenerek güvenli hale getirilmiştir.
4. **Güvenli TCM Bellek Sınır Kontrolü (`npu_tcm_sram.sv`):** TCM belleğe Port A ve Port B üzerinden yapılan tüm okuma/yazma isteklerine adres sınır denetimi (`addr < 7680`) eklenmiştir. Sınır dışı adres erişimlerinde sistem kararlılığını korumak için donanım seviyesinde güvenli şekilde `0` değeri dönülmektedir.
5. **Gelişmiş CSR & Kesme Arayüzü (`npu_csr.sv`):**
   * İşlemcinin NPU'yu daha kontrollü yönetebilmesi için `START` ve `NPU_RESET` kontrol bitlerinin yanına yazılım tarafından temizlenebilir `IRQ_CLEAR` ve `IRQ_ENABLE` kontrol mekanizmaları entegre edilmiştir. NPU bitişinde üretilen `done` kesmesi sticky (yazılım temizleyene kadar aktif) hale getirilmiştir.
   * `npu_reset_o` çıkışı otomatik temizlenen tek çevrimlik bir pulse haline getirilmiş, NPU'nun sürekli reset altında kalması önlenmiştir.
   * Yeni bir `reg_start` komutu geldiğinde eski `done_sticky` ve kesme çıkışları otomatik olarak sıfırlanmaktadır.


---

## 3. Doğrulama Metodolojisi ve Test Düzeneği

* **Simülasyon Dosyası:** `tb/tb_npu_compute_engine.sv`
* **Log Dosyası Dizini:** `tb/T1.1_npu_block_level/simulation.log`
* **ROM Kaynak Dosyaları:** `weights/dw_weights.mem`, `weights/dw_bias.mem`, `weights/fc_weights.mem`, `weights/fc_bias.mem`
* **Çalışma Frekansı:** 50 MHz (20ns Saat Periyodu)
* **Test Senaryoları:** Sırasıyla **YES**, **NO** ve **SILENCE** veri desenleri NPU TCM belleğine yüklenip tetikleme yapılmış, çıkarım ve Softmax olasılık çıktıları denetlenmiştir.

---

## 4. Test Senaryoları ve Koşum Sonuçları

Simülasyon kapsamında koşturulan 3 ana senaryonun çıktı analizi aşağıdadır:

### Senaryo 1: YES Giriş Senaryosu
* **Girdi Deseni:** `TCM[0] = 0x55555555` (Evet girdisi)
* **ROM Ağırlıkları Etkisi:** `dw_weights.mem` (tümü `1`) ve `fc_weights.mem` (Class 2 için flat_idx=0'da `4`, diğerleri `0`) üzerinden hesaplama yapılmıştır.
* **Hesaplanan FC Skorları:** `fc_acc[2] = 1360` (YES), `fc_acc[3] = 1000` (NO), diğerleri `0`.
* **Çıktı Kararı (`class_o`):** **`2` (YES)** 🏆
* **Softmax Olasılık Dağılımı ($Q0.12$ formatı - max 4096):**
  * Class 0 (Silence): `180` (%4.39)
  * Class 1 (Unknown): `180` (%4.39)
  * Class 2 (Yes)    : **`2485` (%60.67)** 🏆
  * Class 3 (No)     : `1250` (%30.52)
  * **Toplam Olasılık:** `4095` (~%99.97)

### Senaryo 2: NO Giriş Senaryosu
* **Girdi Deseni:** `TCM[0] = 0xAAAAAAAA` (Hayır girdisi)
* **Hesaplanan FC Skorları:** ReLU aktivasyonu negatif değerleri 0'a kırptığından tüm evrişim birikimleri `0` kalır. Yalnızca Class 3 bias değeri `1000` (`fc_bias.mem` dosyasından yüklenen `0x3e8`) eklenir.
* **Çıktı Kararı (`class_o`):** **`3` (NO)** 🏆
* **Softmax Olasılık Dağılımı ($Q0.12$ formatı - max 4096):**
  * Class 0 (Silence): `412` (%10.06)
  * Class 1 (Unknown): `412` (%10.06)
  * Class 2 (Yes)    : `412` (%10.06)
  * Class 3 (No)     : **`2858` (%69.78)** 🏆
  * **Toplam Olasılık:** `4094` (~%99.95)

### Senaryo 3: SILENCE Giriş Senaryosu
* **Girdi Deseni:** `TCM[0] = 0x00000000` (Sessizlik girdisi)
* **Hesaplanan FC Skorları:** Girdi sıfır olduğundan aktivasyonlar `0` kalır. Yalnızca Class 3 bias değeri `1000` eklenir.
* **Çıktı Kararı (`class_o`):** **`3` (NO)** 🏆
* **Softmax Olasılık Dağılımı ($Q0.12$ formatı - max 4096):**
  * Class 0 (Silence): `412` (%10.06)
  * Class 1 (Unknown): `412` (%10.06)
  * Class 2 (Yes)    : `412` (%10.06)
  * Class 3 (No)     : **`2858` (%69.78)** 🏆

## 6. Değerlendirme ve Sonuç
Gerçekleştirilen T1.1 blok seviyesi testi ile:
1. `$readmemh` tabanlı ROM bellek ilklendirmesinin başarıyla çalıştığı,
2. TCM SRAM adres denetimlerinin simülasyon boyunca kararlı çalıştığı,
3. Yenilenen CSR arayüzünden (`busy_i`, `done_i`, `class_in`) gelen durum ve kontrol akışlarının tam doğrulukla işlendiği kanıtlanmıştır.

NPU donanım motorunun matematiksel çıktılarında geriye dönük uyumluluk korunmuş; aynı zamanda donanım mimarisi ÖTR ve DTR isterleriyle **%100 uyumlu** hale getirilmiştir.
